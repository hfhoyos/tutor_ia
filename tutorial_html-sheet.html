¿Qué es un Sistema PQRS?

Un sistema de Peticiones, Quejas, Reclamos y Sugerencias (PQRS) representa el canal primario de interacción y retroalimentación entre un usuario y una organización. Tradicionalmente, la clasificación, enrutamiento y priorización de estas solicitudes se realiza mediante procesos manuales propensos a cuellos de botella e inconsistencias de criterio humano.

Matriz DOFA Estratégica: El Enfoque del Ecosistema Automatizado

Analizando la infraestructura tecnológica clásica frente al paradigma de AI Engineering, identificamos una ventana de oportunidad única al conectar aplicaciones desacopladas con motores lógicos inteligentes soportados en hojas de cálculo asíncronas:

Debilidades (Sistemas Tradicionales)

  • Clasificación manual lenta y subjetiva de las PQRS.
  • Falta de respuestas inmediatas o acuses de recibo estructurados.
  • Fragmentación de datos por almacenamiento local aislado.

Oportunidades (La Gran Ventana)

Generar una Web App ligera conectada a Google Sheets mediante Apps Script como canal asíncrono y OpenAI como motor lógico. Permite democratizar el uso de IA empresarial sin requerir costos de servidores dedicados ni bases de datos SQL complejas.

Fortalezas del Ecosistema Prouesto

  • Costo de infraestructura cercano a cero utilizando recursos Cloud nativos.
  • Clasificación y análisis semántico en tiempo real (menos de 3 segundos).
  • Desacoplamiento total entre la interfaz de usuario (Recepción) y el almacén persistente (Planta Baja).

Amenazas del Entorno

  • Exposición o filtración de API Keys si se exponen en el lado del cliente (resuelto delegándolo al Sótano).
  • Dependencia de la disponibilidad de los endpoints de la API externa.

Descripción General de la Aplicación

La solución se despliega bajo la arquitectura de la Metodología Torres, organizando la aplicación en componentes funcionales totalmente autónomos:

  • La Recepción (Frontend - index.html): Una interfaz táctil, limpia y elegante inspirada en las guías de interfaz humana de Apple. Captura los datos mínimos del usuario y los despacha mediante una llamada asíncrona ciega, mitigando problemas de CORS.
  • El Sótano (Middleware - Código Apps Script): Funciona como el motor oculto de orquestación y lógica de negocio. Recibe el impacto del frontend, interactúa de servidor a servidor con los modelos de lenguaje de OpenAI usando esquemas JSON estructurados rígidos, y escribe la traza limpia en la base de datos.
  • La Planta Baja (Persistencia - Google Sheets): El repositorio centralizado donde se asientan las filas de datos enriquecidos por la IA, permitiendo la visualización directa e inmediata del estado del laboratorio.

Requerimientos del Sistema

Requerimientos Funcionales (RF)

  1. RF-01 Captura de Datos: El sistema debe proveer campos limpios para nombre del remitente y redacción libre de la PQRS.
  2. RF-02 Enriquecimiento por IA: El backend debe invocar de forma imperativa un modelo GPT para clasificar la solicitud en categorías (Petición, Queja, Reclamo, Sugerencia) y prioridades (Alta, Media, Baja) sin intervención humana.
  3. RF-03 Persistencia Asíncrona: Se debe inyectar de forma atómica cada registro en una fila de la matriz activa de Google Sheets incluyendo marcas temporales exactas.

Requerimientos No Funcionales (RNF)

  1. RNF-01 Seguridad de Credenciales: La clave API de OpenAI debe permanecer estrictamente oculta en variables de entorno del servidor (Sótano), jamás expuesta en el código del navegador del cliente.
  2. RNF-02 Estética de Interfaz: El diseño gráfico debe implementar propiedades visuales avanzadas: transparencias de fondo (Glassmorphism), fuentes tipográficas del sistema y bordes suavizados con un radio uniforme de 12 a 16px.
  3. RNF-03 Compatibilidad Cruzada (No-CORS): La comunicación debe ejecutarse en modo opaco para posibilitar el transporte directo entre servidores locales de prueba y las instancias Cloud de Google.

Roadmap y Secuencia de Construcción del Ecosistema

Sigue esta línea de tiempo procedimental diseñada para asegurar la repetibilidad absoluta del entorno técnico por parte de los aprendices:

Paso 1: Inicialización de la Matriz Persistente (Planta Baja)

Crear la hoja de cálculo de Google Drive y estructurar las primeras 6 columnas de la fila de cabecera de forma exacta.

Entregable esperado: Archivo de Google Sheet con las cabeceras: IDFecha, Remitente, Redacción Original, Categoría, Prioridad y Análisis. Enlace de visibilidad configurado en modo público de lectura.

Paso 2: Implementación de la Lógica del Sótano (Apps Script)

Abrir el editor de código integrado en la hoja de cálculo, vaciar el entorno y transcribir las rutinas de comunicación del backend.

Entregable esperado: Archivo index.gs guardado, con la función pruebaEscritura ejecutada con éxito y permisos de seguridad del usuario explícitamente autorizados.

Paso 3: Publicación y Despliegue del Web Service Container

Compilar y desplegar el script bajo la modalidad de aplicación web con permisos de acceso universales.

Entregable esperado: URL de producción única de Google que termina con el sufijo de ejecución segura /exec.

Paso 4: Sincronización y Orquestación del Cliente (Recepción)

Configurar el archivo HTML local, inyectando la URL generada del script en la variable fetch de la interfaz de usuario.

Entregable esperado: Archivo index.html operativo localmente. Al ingresar una solicitud de prueba, esta debe aparecer clasificada por la IA en la hoja de Google Sheets en menos de 5 segundos.

Análisis de Estructura e Instrumentación

¿Dónde agregar la API Key?
Modifica la línea 1 reemplazando el valor asignado a la constante API_KEY con tu token secreto provisto por la plataforma de OpenAI.

Puntos Clave del Backend:

  • doPost(e): Intercepta las transmisiones entrantes de la web de forma nativa.
  • llamarCerebroIA(): Construye un prompt estricto forzando al LLM a comportarse como un analizador determinista que responde única y exclusivamente cadenas estructuradas legibles en JSON.
  • hoja.appendRow(): Modifica la Planta Baja insertando los datos en una operación atómica.

¿Dónde agregar la URL de conexión?

Evolución del Ecosistema y Siguiente Escalón Tecnológico

El horizonte de desarrollo de la solución prevé la transición hacia experiencias más ricas e integradas para el tratamiento inteligente de solicitudes:

1. Módulo de Chat por Voz

Integración de API de Web Audio nativa para capturar la voz del usuario desde la Recepción, despachando el flujo binario a los endpoints de Speech-to-Text de OpenAI (Whisper). Esto permitirá a la IA procesar la transcripción y mantener la consistencia en la inyección de datos estructurados en la Planta Baja sin requerir digitación manual.

2. Canal de Voz Premium (Omnicanalidad)

Despliegue de un pipeline avanzado de respuesta conversacional bidireccional en tiempo real. Utilizando síntesis de voz fidedigna (Text-to-Speech adaptativo), el sistema no solo clasificará el incidente de forma interna, sino que responderá al usuario verbalmente con el resumen analítico generado por el cerebro de IA, simulando una llamada interactiva con un agente experto.
